# 🐍 Mirror-V Python Worker 目录结构与规范 (v0.1.0)

## 1. 物理目录树 (Directory Tree)

Antigravity，请严格按照以下结构在虚拟机 `/opt/Mirror-v-0.1.0/mirror-v-worker` 路径下创建目录：

Plaintext

```
mirror-v-worker/
├── main.py                # 核心入口：负责 Redis 队列监听与任务调度
├── config.py              # 全局配置：数据库连接串、Redis 地址、Dify API Key
├── requirements.txt       # 依赖清单：必须包含 opencv-python, whisper, psycopg2
├── core/                  # 【业务逻辑层】
│   ├── __init__.py        # 标识为包
│   ├── video_processor.py # 封装 OpenCV 抽帧逻辑
│   ├── audio_processor.py # 封装 Whisper 语音转文字逻辑
│   └── dify_client.py     # 封装 Dify 工作流 API 调用
├── db/                    # 【数据持久层】
│   ├── __init__.py        # 标识为包
│   └── models.py          # 封装 Postgres 增删改查 (SQL 操作)
└── utils/                 # 【公共工具层】
    ├── __init__.py        # 标识为包
    └── logger.py          # 统一日志格式化输出
```

## 2. 各模块核心职责 (Responsibilities)

| **模块**    | **职责描述**                                                 | **对应 Java 层级参考**     |
| ----------- | ------------------------------------------------------------ | -------------------------- |
| `main.py`   | 使用 `blpop` 阻塞监听 Redis，获取任务后分发给 core 模块。    | 相当于 Controller/Consumer |
| `core/`     | 纯净的算法与业务逻辑，不直接操作数据库。                     | 相当于 Service 层          |
| `db/`       | 负责将解析结果写入 `video_assets` 和 `ai_analysis_reports`。 | 相当于 Repository/DAO 层   |
| `config.py` | 读取环境变量，提供统一的连接池配置。                         | 相当于 application.yml     |

：

3. 协作开发契约 (Contract Hints)

- **路径引用**：在代码中引用图片存储路径时，必须统一使用 `../storage/` 作为相对路径根目录。
- **数据库操作**：所有数据库操作必须使用 `db/models.py` 中的函数，禁止在 `main.py` 中直接写 SQL。
- **日志规范**：所有处理环节必须打印 `[TaskID: xxx] Starting/Finished ...` 以便联调排查。
